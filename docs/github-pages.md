# GitHub Pages への公開

GitHub Pages は HTML/CSS/JavaScript 用の静的ホスティングです。Python サーバー、SQLite、Tesseract、Drive 認証、OpenAI API の処理は Pages 上では実行できません。

このアプリはサーバー版とPagesの両方で、**同梱の練習問題230問／教科書問題662問を選択**できます。JSONファイル本体を配信するため、Google Driveへのアクセスや手動インポートは不要です。初期選択は教科書問題で、初期画面で問題集・出題範囲・出題数を選んでから練習画面に進みます。範囲・出題数の初期値は「すべて」「全問」です。問題集を切り替えると国と件数を再集計し、回答・得点・進捗を消して初期設定に戻します。読み込んだだけでは出題を開始しません。両版は共通の練習専用2画面UIを使用します。回答や手動で読み込んだ内容は現在のタブのメモリに保持し、外部サービスに送信しません。ページを再読み込みすると教科書問題に戻ります。

両問題集とも全問 `auto_checked` で、人による最終確認前です。練習問題は13か国230問で、元設問・解答表の対応、編集記録、年度不明の統計への注記を引き継ぎます。教科書問題は12か国662問で、元の864項目のうち816項目は問題または解説に対応し、35項目は関連特徴のみ扱い、13項目は保留です。全項目を完全網羅したという意味ではありません。対応先と理由は [知識ID別の対応表](../question-packs/coverage.json) に記録しています。構造・正答キーの機械検証は、誤答の意味上の一意性や原資料との照合・承認を保証しません。回答後は元データの `knowledge_id`・`source_page` を出典として表示します。

## 初回設定

1. [対象リポジトリの Settings → Pages](https://github.com/boqxxxpod/wine-quiz-master/settings/pages) を開きます。
2. **Build and deployment → Source → GitHub Actions** を選択します。
3. [Deploy GitHub Pages ワークフロー](https://github.com/boqxxxpod/wine-quiz-master/actions/workflows/pages.yml) を実行します。失敗済みの実行があれば **Re-run all jobs** を選びます。
4. deploy ジョブが成功したら、実行結果の `github-pages` 環境に表示される URL を開きます。

リポジトリが非公開の場合、GitHub Pages を使える Pro/Team/Enterprise の契約が必要です。ソースの非公開設定と公開サイトの閲覧制限は別です。リポジトリを自動で公開に変更することはありません。

初回の Pages 有効化は Pages と Administration の書き込み権限が必要です。通常の `GITHUB_TOKEN` では初回有効化できません。以後は `main` への push でビルド・公開が実行されます。初回設定がない場合は configure-pages ステップで停止します。

## 公開するファイル

```sh
python scripts/build_pages.py
```

`dist-pages/` に公開成果物を作ります。許可した `index.html`、`static/` のフロントエンドファイルと、次の二つの問題集だけをコピーし、実行モードを `pages` に固定します。

| 選択肢 | 公開するJSON |
| --- | --- |
| 練習問題 | `question-packs/wine-quiz-practice-20261031.json` |
| 教科書問題 | `question-packs/wine-quiz-highlighted.json` |

両JSONはリポジトリ内の元ファイルのバイト列を保ちます。旧500問版・旧150問版や確認用バッチ、対応表、検証レポートは含みません。ワークフローはこのディレクトリだけをアップロードします。サーバー版も `/question-packs/{filename}` の許可リストで上記二件だけを公開し、問題集ディレクトリ全体は公開しません。

`.env`、Google 認証、原本写真、OCR、SQLite、個別に生成した問題、確認用スクリーンショット、`data/`、Python ソースを公開成果物に含めません。同梱JSONのいずれかがない場合はビルドを失敗させ、空の問題集に置き換えません。ビルド失敗時には直前の完成済み成果物を保持します。シンボリックリンクを通じて別ファイルを公開することも拒否します。

## 出題範囲

「すべて」は全問題を対象とし、「国別」は国を1つ選択して `countries.includes(選択国)` を満たす問題だけを対象にします。初期画面に対象件数を表示し、出題数は5・10・20・30・50・70・100・全問から選べます。範囲の件数を超える固定値は無効にします。範囲を変えて選択数が超過した場合は全問に戻します。開始時にも値を検証し、不正値や0問では開始できません。

開始時は対象から指定数をランダムに抽出し、回答・得点・進捗をリセットして練習画面に進みます。進捗・得点の分母・終了判定は指定数です。「もう一巡」は同じ範囲と出題数で再抽出・シャッフルし、一巡中の重複を防ぎます。選択肢もシャッフルし、元データが指定する正解を ID で維持します。「設定に戻る」で条件を変更して、新しい練習を開始できます。解説は省略せず表示し、結果の近くに次へ進むボタンを固定しています。

画面の出題範囲と件数は選択中の問題集の `countries` から決定します。「すべて・全問」は練習問題230問、教科書問題662問です。ドイツ14問は練習問題を選んだ場合だけ表示します。教科書問題には複数国に属する問題があるため国別の合計は666ですが、「すべて」では各IDを1問として数えます。全ての国別件数は [README](../README.md#問題集範囲出題数) に記載しています。

ビルドでは両JSONを含む公開ファイルの内容から版番号を作り、HTMLの入口だけでなく、app.jsからpages.js・quiz.jsへのモジュール読み込みにも同じ版を付けます。選択した問題集の取得URLにも版を伝え、JSONを再取得します。アプリの配置場所に対する相対URLを使うため、`/wine-quiz-master/` のようなサブパスでも取得できます。サーバー版の直接配信にも版付きモジュールを使います。

選択したファイルの取得や検証に失敗した場合は、対象ファイル名と理由を表示して出題を停止し、同じ問題集を再読み込みできます。他方の問題集への自動切り替えは行いません。未知の形式、不正な正解ID、重複IDなどは問題集全体を拒否します。読み込み中は問題集の選択・手動取り込み・開始を無効化します。

## 別の問題集を手動で読み込む

サーバー版とPagesのどちらでも、初期画面の「別の問題集 JSON」でpilot形式、従来のネイティブ30問形式、承認済み書き出しの `version: 1` 形式を読み込めます。手動ファイルを使用中は練習問題・教科書問題のラジオ選択を解除します。「練習問題に戻す／教科書問題に戻す」は直前に選んでいた組み込み問題集を再取得して進捗をリセットします。各ラジオからも組み込み問題集に切り替えられます。

サーバーで生成・承認した問題を練習する手順は次のとおりです。承認しても同梱問題集には自動追加されません。

1. サーバー管理APIで写真を取り込み、黄色部分を照合して生成問題を承認します（[管理APIの手順](../README.md#google-ドライブの接続)）。練習画面には取り込み・承認の操作はありません。
2. サーバーの実行環境で次のコマンドを実行します。

```sh
.venv/bin/python scripts/export_questions.py
```

3. `data/exports/questions.json` を手元の端末へ保存し、サーバー版または Pages の **別の問題集 JSON** で選択します。この JSON を Git に追加する必要はありません。

最新の写真版に対応する承認済み問題だけをエクスポートします。三択と正解ID、解説、写真ファイル名、黄色部分の引用を保持します。読み込み上限は2 MB・2,000問です。不正な問題集は全体を拒否し、すでに読み込んだ問題と回答状況を保持します。

従来形式に国情報がない場合は「すべて」で練習します。ファイルの選択に失敗したり、不正な内容だったりした場合は、直前に読み込んだ問題集名・問題・回答状況を保持してエラーを表示します。Pages には原本写真を送らないため、画像・黄色マスクとの照合と承認はサーバー版で行います。従来の写真取り込みで保存されている実資料は要確認で、同梱問題集とは別です。

## 公開前の確認

PRの `Validate quiz and application` ワークフローで次を実行します。Node.jsの画面操作テストは合成DOM上で行い、組み込み問題集の切り替え、8つの出題数での一巡・再開・範囲変更を確認します。

```sh
python -m unittest discover -s tests -v
node --test tests/*.mjs
node scripts/verify_standard_pack.mjs
python scripts/build_pages.py
```

データ検証は教科書662問・既存500問と150問の保持・国別件数・14バッチ一致・864項目の対応分類・2 MB以内を含みます。Node.jsテストでは練習問題230問・13か国の件数、正答キー、編集・統計注記の保持と、両問題集の国別・出題数別の出題と採点も確認します。Pagesの両JSONは元と同じバイト列です。旧版・分割版・対応表・原画像が公開成果物に含まれないこと、どちらのJSONを更新しても読み込みモジュールの版が変わることをテストします。

実行結果と画面サイズ別の実ブラウザ確認は [確認記録](verification.md) に残しています。自動テストの成功は問題内容の人による最終承認を意味しません。教科書問題の未解決の知識と既存問題に残る制約は [検証レポート](../question-packs/highlighted-validation-report.md) に記録しています。
