# GitHub Pages への公開

GitHub Pages は HTML/CSS/JavaScript 用の静的ホスティングです。Python サーバー、SQLite、Tesseract、Drive 認証、OpenAI API の処理は Pages 上では実行できません。

このアプリはサーバー版を残し、Pages でも **同梱150問を自動で読み込み**ます。初期画面でユーザー指定の `question-packs/pilot-150.json` を取得し、問題集・出題範囲・出題数を選んでから練習画面に進みます。初期値は「すべて」「全問」で、読み込んだだけでは出題を開始しません。サーバー版も同じファイルと練習専用の2画面UIを使用し、タブや資料・接続設定への導線はありません。問題への回答や手動で読み込んだ内容は現在のタブのメモリに保持し、外部サービスに送信しません。再読み込みすると回答状況と手動読み込みは消え、同梱問題集を再取得します。

150問は全て `auto_checked` の試験運用データで、人による最終確認前です。構造・正答キーの機械検証は、誤答の意味上の一意性や原資料との照合・承認を保証しません。回答後は元データの `knowledge_id`・`source_page` を出典として表示します。

## 初回設定

1. [対象リポジトリの Settings → Pages](https://github.com/boqxxxpod/wine-quiz-master/settings/pages) を開きます。
2. **Build and deployment → Source → GitHub Actions** を選択します。
3. [Deploy GitHub Pages ワークフロー](https://github.com/boqxxxpod/wine-quiz-master/actions/workflows/pages.yml) を実行します。失敗済みの実行があれば **Re-run all jobs** を選びます。
4. deploy ジョブが成功したら、実行結果の `github-pages` 環境に表示される URL を開きます。

リポジトリが非公開の場合、GitHub Pages を使える Pro/Team/Enterprise の契約が必要です。ソースの非公開設定と公開サイトの閲覧制限は別です。リポジトリを自動で公開に変更することはありません。

初回の Pages 有効化は Pages と Administration の書き込み権限が必要です。通常の `GITHUB_TOKEN` では初回有効化できません。以後は `main` への push でビルド・公開が実行されます。初回設定がない場合は configure-pages ステップで停止します。

## 公開するファイル

```sh
python scripts/build_pages.py
```

`dist-pages/` に公開成果物を作ります。許可した `index.html`、`static/` のフロントエンドファイル、`question-packs/pilot-150.json` だけをコピーし、実行モードを `pages` に固定します。JSON は元ファイルのバイト列を保ち、公開対象をこの1ファイルに限定します。ほかの JSON や30問ずつの確認用バッチは含みません。ワークフローはこのディレクトリだけをアップロードします。サーバー版も `/question-packs/pilot-150.json` だけを公開し、問題集ディレクトリ全体は公開しません。

`.env`、Google 認証、原本写真、OCR、SQLite、個別に生成した問題、確認用スクリーンショット、`data/`、Python ソースを公開成果物に含めません。同梱 JSON がない場合はビルドを失敗させ、空の問題集に置き換えません。ビルド失敗時には直前の完成済み成果物を保持します。シンボリックリンクを通じて別ファイルを公開することも拒否します。

## 出題範囲

「すべて」は全問題を対象とし、「国別」は国を1つ選択して `countries.includes(選択国)` を満たす問題だけを対象にします。初期画面に対象件数を表示し、出題数に「全問」か範囲内の整数を選べます。上限を超える指定や不正な値では開始できず、範囲・問題集の変更時も上限と選択値を合わせます。

開始時は対象から指定数をランダムに抽出し、回答・得点・進捗をリセットして練習画面に進みます。進捗・得点の分母・終了判定は指定数です。「もう一巡」は同じ範囲と出題数で再抽出・シャッフルし、一巡中の重複を防ぎます。選択肢もシャッフルし、元データが指定する正解を ID で維持します。「設定に戻る」で条件を変更して、新しい練習を開始できます。解説は省略せず表示し、結果の近くに次へ進むボタンを固定しています。

実際の問題を集計した件数は、すべて150問、フランス32問、スペイン16問、イタリア・日本各17問、アメリカ・オーストラリア・ポルトガル各11問、オーストリア8問、ニュージーランド・アルゼンチン・南アフリカ・チリ各7問です。`Q-K0019-01` はフランスとスペインの両方に属し、両国の範囲に含まれます。「すべて」では1問なので、国別件数の合計151問とは一致しません。

元ファイルの `metadata.country_counts` はスペインを15問と記録していますが、出題範囲と件数は各問題の `countries` から集計した16問です。元ファイルのメタデータをそのまま保持し、画面の件数には使いません。

初期ファイルの取得や検証に失敗した場合は、対象ファイル名と理由を表示し、出題を停止します。未知の形式、不正な正解 ID、重複 ID などは問題集全体を拒否します。

## 別の問題集を手動で読み込む

サーバー版と Pages のどちらでも、初期画面の「別の問題集 JSON」で pilot 形式、従来のネイティブ30問形式、承認済み書き出しの `version: 1` 形式を読み込めます。「標準問題集に戻す」は手動ファイルを取り除き、同梱150問を再取得して進捗をリセットします。

サーバーで生成・承認した問題を練習する手順は次のとおりです。承認しても同梱問題集には自動追加されません。

1. サーバー管理APIで写真を取り込み、黄色部分を照合して生成問題を承認します（[管理APIの手順](../README.md#google-ドライブの接続)）。練習画面には取り込み・承認の操作はありません。
2. サーバーの実行環境で次のコマンドを実行します。

```sh
.venv/bin/python scripts/export_questions.py
```

3. `data/exports/questions.json` を手元の端末へ保存し、サーバー版または Pages の **別の問題集 JSON** で選択します。この JSON を Git に追加する必要はありません。

最新の写真版に対応する承認済み問題だけをエクスポートします。三択と正解ID、解説、写真ファイル名、黄色部分の引用を保持します。読み込み上限は2 MB・2,000問です。不正な問題集は全体を拒否し、すでに読み込んだ問題と回答状況を保持します。

従来形式に国情報がない場合は「すべて」で練習します。ファイルの選択に失敗したり、不正な内容だったりした場合は、直前に読み込んだ問題集名・問題・回答状況を保持してエラーを表示します。Pages には原本写真を送らないため、画像・黄色マスクとの照合と承認はサーバー版で行います。従来の写真取り込みで保存されている実資料は要確認で、同梱問題集とは別です。

## 公開前の確認

次のコマンドで Python 49件、JavaScript 64件（読み込み16件・出題ロジック16件・画面操作32件）が成功しました。画面操作の自動テストは Node.js 上の合成 DOM で実行し、実ブラウザでも別途検証しました。

```sh
.venv/bin/python -m unittest discover -s tests -v
node --test tests/*.mjs
# 実ファイルの150問・国別件数・共有問題を検証
node scripts/verify_standard_pack.mjs
```

実ファイルで150問・全12か国の件数・`Q-K0019-01` の両国への所属・正答キー・5バッチとの本文一致・不要な準拠表現の除去を確認し、Pages ビルドも成功しました。公開成果物の JSON は編集済み統合ファイルと同じバイト列です。今回のJSON本文の編集は `question`・`explanation` だけで、スキーマ変更はありません。境界条件や不正ファイルには合成データを使いました。

実際の FastAPI サーバーと `/wine-quiz-master/` 配下の Pages 成果物を Chromium で確認しました。1440px で全150問を重複なく一巡して150点、360px でフランス32問・スペイン16問を一巡し、共有問題が両方に含まれることを確認しました。同じ範囲での再開・得点リセット、`knowledge_id`・`source_page`・トピック・`auto_checked`・人手確認前の表示も確認しています。横方向のはみ出し、JavaScript・HTTP エラー、外部リクエストはなく、Pages の API 通信は0件でした。機械検証と動作確認の成功は、人による問題内容の最終確認を意味しません。
